Space Quiz を GitHub Pages で公開し、誰でもアクセスできるようにします。Copilot はワークフローの準備とデプロイの案内を行えますが、変更をレビューし、サイトが公開されたことを確認するのはユーザーの責任です。

このレッスンでは、次の内容を学習します。

- Copilot に GitHub Pages のデプロイ構成を依頼します。
- マージする前にワークフローとプルリクエストをレビューします。
- デプロイの状況を追跡し、公開されたサイトを確認します。

## シナリオ

Space Quiz はすでに GitHub リポジトリにありますが、誰でも簡単に試せる方法が必要です。単一ファイルのサイトを GitHub Pages で公開すると、サーバーやランタイム依存関係を追加せずに、公開 URL からアクセスできるようになります。

## Copilot にデプロイの準備を依頼する

> [!WARNING]
> プルリクエストを作成すると、コードがコミットおよびプッシュされる場合があります。このプロンプトを送信する前に、承認設定と送信先リポジトリを確認してください。**Approve all** を選択している場合、別途確認が求められるとは限りません。

`space-quiz` の Copilot アプリのセッションで、次のプロンプトを送信します。

```plaintext
このリポジトリで GitHub Pages に公開する準備をしてください。変更がデフォルトブランチに反映された後、必要に応じてウェブサイトをビルドし、GitHub Pages にデプロイする GitHub Actions ワークフローを作成してください。README がまだない場合は、アプリの説明とローカルでの実行方法を記載した README を追加してください。これらの変更でプルリクエストを作成し、そのリンクと必要な Pages の設定または権限を報告してください。マージ、自動マージの有効化、Pages 設定の変更、デプロイは行わないでください。作業を停止して、私のレビューを待ってください。
```

## ワークフローとプルリクエストをレビューする

1. README がリポジトリにまだない場合に限り、追加されていることを確認します。
2. ワークフローのビルドとデプロイの手順、トリガー、権限を含め、プルリクエストの変更をレビューします。
3. マージされていないプルリクエストではなく、デフォルトブランチからデプロイすることを確認します。
4. 必要な修正を依頼し、更新された diff をレビューします。マージを許可する前に、必須のプルリクエストチェックが成功するまで待ちます。

## マージとデプロイを許可する

> [!WARNING]
> 次のプロンプトは、レビュー済みのプルリクエストのマージ、リポジトリの Pages 設定の変更、サイトの公開をエージェントに許可します。レビューを完了し、リポジトリとプルリクエストを確認した後にのみ送信してください。承認設定によっては、これらの操作が別の確認なしに実行される場合があります。

`<PR_NUMBER>` をレビューしたプルリクエスト番号に置き換え、次のプロンプトを別途送信します。

```plaintext
このリポジトリのプルリクエスト <PR_NUMBER> をレビューし、マージとデプロイを許可します。GitHub Actions を使う GitHub Pages を有効にし、必須チェックが成功した後に限り、そのプルリクエストをマージしてください。デプロイが成功するまで状況を監視し、公開されたウェブサイトの最終 URL を報告してください。Pages の有効化やマージに必要な権限がない場合は、私が何を承認または実行すればよいか正確に説明してください。サイトが実際に公開されるまで、成功したと報告しないでください。
```

## デプロイを確認する

1. GitHub Actions のデプロイ実行が成功するまで確認します。
2. 報告された URL を開き、Space Quiz が読み込まれることを確認します。

エージェントが Pages の有効化やプルリクエストのマージを行えない場合は、提示された具体的な手順に従います。デプロイが成功し、公開サイトが読み込まれるまで、タスクを完了したと見なさないでください。
